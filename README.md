# کراولر محصولات

سرویس وب برای جمع‌آوری محصولات سایت‌های فروشگاهی (ووکامرس و سایت‌های عمومی). آدرس سایت را وارد می‌کنید و خروجی Excel / CSV / JSON تحویل می‌گیرید.

## فایل‌ها

| فایل | کار |
|---|---|
| `app.py` | سرور وب و API (فقط کتابخانه‌ی استاندارد پایتون) |
| `static/index.html` | صفحه‌ی فارسی |
| `crawler.py` | موتور کراول؛ از خط فرمان هم قابل اجراست |
| `render.yaml` | تنظیمات دیپلوی روی Render |

## دیپلوی روی Render

1. این پوشه را در یک ریپوی GitHub قرار دهید.
2. در Render: **New → Blueprint** و ریپو را انتخاب کنید. Render خودش `render.yaml` را می‌خواند.
3. مقدار `APP_PASSWORD` را بخواهد، یک رمز بگذارید.
4. بعد از دیپلوی، آدرس `https://<نام>.onrender.com` را باز کنید. نام کاربری هر چیزی می‌تواند باشد و رمز همان `APP_PASSWORD` است.

## چه چیزهایی جمع‌آوری می‌شود

| بخش | جزئیات |
|---|---|
| اطلاعات پایه | نام، لینک، شناسه، SKU، برند، دسته‌بندی، برچسب‌ها |
| قیمت | قیمت، قیمت اصلی/حراج، بازه‌ی قیمت محصولات متغیر، تومان/ریال، موجودی |
| محتوا | توضیح کوتاه، توضیحات کامل (متن و HTML تمیز)، عنوان و توضیح متای صفحه |
| مشخصات | ویژگی‌های ووکامرس + جدول‌ها و لیست‌های «کلید: مقدار» داخل توضیحات و تب‌ها |
| عکس‌ها | عکس اصلی، گالری (نسخه‌ی اصلی، نه تامبنیل)، عکس‌های داخل توضیحات |
| فایل‌ها | لینک PDF/کاتالوگ/فایل‌های دانلودی صفحه‌ی محصول |

گزینه‌ها در صفحه:

- **عکس‌ها:** «فقط لینک»، «دانلود عکس اصلی» (پیش‌فرض) یا «دانلود همه‌ی عکس‌ها» (حداکثر ۱۵ عکس برای هر محصول). عکس‌های دانلودشده در یک ZIP می‌آیند و عکس اصلی به‌صورت تصویر کوچک داخل Excel قرار می‌گیرد.
- **محتوای کامل هر محصول:** وقتی API ووکامرس جواب می‌دهد، صفحه‌ی هر محصول را هم باز می‌کند تا گالری، جدول مشخصات و فایل‌ها را بگیرد. کندتر است ولی کامل‌تر.

- **فقط محصولات موجود و قیمت‌دار:** محصولات ناموجود و بدون قیمت (مثل «تماس بگیرید») در خروجی نمی‌آیند و عکسشان دانلود نمی‌شود. در سایت‌هایی که API ووکامرس باز است، از خود API فقط کالاهای موجود گرفته می‌شود و صفحه‌ی محصولات ردشده اصلاً باز نمی‌شود. در سایت‌هایی که صفحه‌به‌صفحه خوانده می‌شوند، هر صفحه باید باز شود تا معلوم شود قیمت دارد یا نه. تعداد ردشده‌ها در صفحه نشان داده می‌شود.
- **سرعت:** آرام (۱ صفحه در ثانیه)، معمولی (۲) یا سریع (۴). اگر سایت در robots.txt مقدار `Crawl-delay` تعیین کرده باشد، همان رعایت می‌شود.

### ساختار Excel

- **محصولات:** یک ردیف برای هر محصول؛ ستون تصویر، یک ستون برای هر عکس (عکس ۱، عکس ۲، …) و یک ستون برای هر مشخصه (تا ۴۰ مشخصه‌ی پرتکرار).
- **مشخصات:** همه‌ی مشخصات به‌صورت «محصول / ویژگی / مقدار»؛ مناسب فیلتر و Pivot.
- **عکس‌ها:** همه‌ی لینک‌های عکس هر محصول با نام فایل دانلودشده.

## متغیرهای محیطی

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `APP_PASSWORD` | خالی (بدون رمز) | رمز صفحه و API |
| `MAX_CONCURRENT_JOBS` | `2` | تعداد کراول هم‌زمان |
| `CRAWLER_PROXY` | — | پروکسی برای سایت‌هایی که IP خارجی را می‌بندند |
| `DATA_DIR` | `/tmp/crawler-jobs` | محل ذخیره‌ی خروجی‌ها |
| `MAX_IMAGE_MB` | `1500` | سقف حجم عکس‌های دانلودی هر کار |
| `MEM_LIMIT_MB` | `512` | حافظه‌ی سرور (برای توقف ایمن پیش از پر شدن) |
| `DIAG_URLS` | — | (عیب‌یابی) آدرس‌هایی که هنگام شروع، ساختارشان در لاگ نوشته می‌شود |

## API

```bash
# شروع کراول
curl -u x:PASS -X POST https://<app>.onrender.com/api/jobs \
     -d '{"url":"https://tsaco-diesel.com","images":"main","enrich":true,"only_available":true,"delay":0.5}'
# وضعیت
curl -u x:PASS https://<app>.onrender.com/api/jobs/<id>
# دانلود (xlsx / csv / json / zip)
curl -u x:PASS -o out.xlsx https://<app>.onrender.com/api/jobs/<id>/download/xlsx
```

## سایت‌های خاص

- **فروشگاه‌های غیر ووکامرسی** (مثل سایت‌های اختصاصی): صفحه‌هایی که آدرسشان شبیه صفحه‌ی محصول است (`/product/...`) به‌عنوان محصول خوانده می‌شوند؛ نام از عنوان یا مسیر صفحه، کد محصول و برند از برچسب‌هایی مثل «کد محصول : …»، و مشخصات از لیست‌ها و جدول‌ها.
- **لیست قیمت جدولی:** هر ردیف جدولی که ستون «قیمت» دارد یک محصول می‌شود؛ ردیف‌های عنوان گروه (مثل «۵۰۰ تا ۱۰۰۰ کاوآ») به‌عنوان دسته‌بندی ثبت می‌شوند. لیست‌هایی که داده‌شان به‌صورت JSON داخل صفحه است (و با جاوااسکریپت جدول می‌سازند) هم خوانده می‌شوند. حالت «لیست قیمت / جدول» جدول‌های بدون ستون قیمت را هم برمی‌دارد.
- **زیردامنه‌ها:** لینک به زیردامنه‌های همان سایت (مثل `list.example.com`) دنبال می‌شود؛ زیردامنه‌هایی مثل `blog.` و `mail.` نادیده گرفته می‌شوند.

## پایداری

- خروجی‌ها مستقیم از فایل روی دیسک ساخته می‌شوند، نه از حافظه؛ برای هزاران محصول هم حافظه‌ی کمی لازم است.
- اگر حافظه‌ی سرور به ۸۲٪ برسد، کار به‌صورت امن متوقف و خروجی ساخته می‌شود (نه اینکه سرور از کار بیفتد).
- وضعیت کارها روی دیسک ذخیره می‌شود. اگر سرور ری‌استارت شود، کار با وضعیت «قطع شد» و محصولات جمع‌شده برمی‌گردد. دکمه‌ی **«ادامه از همین‌جا»** کار را بدون تکرار محصولات قبلی ادامه می‌دهد.

## روش کار کراولر

برای هر سایت به ترتیب امتحان می‌کند:

1. **API ووکامرس** (`/wp-json/wc/store/v1/products`) — سریع‌ترین
2. **سایت‌مپ** محصولات و خواندن صفحه‌ها
3. **پیمایش لینک‌ها** از صفحه‌ی اصلی

اطلاعات از JSON-LD، OpenGraph و HTML ووکامرس خوانده می‌شود. robots.txt رعایت می‌شود.

## نکات پلن رایگان Render

- بعد از ۱۵ دقیقه بدون درخواست می‌خوابد. وقتی صفحه باز است بیدار می‌ماند، پس صفحه را تا پایان کراول باز نگه دارید.
- با هر ری‌استارت یا دیپلوی، خروجی‌ها پاک می‌شوند. فایل را همان موقع دانلود کنید.
